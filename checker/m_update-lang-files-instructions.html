Translation Update Instructions

Read this once before uploading. Most issues are caused by the column order being changed or by uploading the wrong file format.

1How this upload works

Uploads are merged with the existing translations. Keys that are not in your file are kept as-is — they are not deleted. This means you can upload a small file containing only the keys you are adding or updating; you do not need to include all 8,000 keys every time.

Empty cells in your file mean “leave the existing value alone”. The importer will not clear or remove an existing translation just because the cell is empty in your upload. Removing or replacing existing translations is done by uploading the new value in the same cell.

Do not rearrange columns. The importer trusts the column position to identify each language. If you accidentally insert a column or move one, values will be written to the wrong language file and you will not see an error. Always start from the master template.

2How to update existing translations

  1. Open the master XLS template.
  2. Add a row for each key you want to update. Put the key in column A.
  3. Fill the languages you want to change with the new values.
  4. Leave empty any languages you don't want to touch.
  5. Save as .xls (Excel 97–2003 Workbook), not .xlsx.
  6. Use the upload form below.
A B (il_HE) C (il_HEBAK) D (il_HES) E (en_US) F (en_AU) …
┌─────────────┬───────────┬─────────────┬───────────┬───────────┬───────────┐
│ save │ (empty) │ (empty) │ (empty) │ Save now │ (empty) │
│ cancel │ (empty) │ (empty) │ (empty) │ Cancel │ (empty) │
└─────────────┴───────────┴─────────────┴───────────┴───────────┴───────────┘

In the example above, only the en_US values for save and cancel are being updated. All other languages and all other keys remain unchanged.

3How to update only one language

To update just one language, put the new value in that language's column and leave every other language column empty in the same row. The merge logic preserves all the empty cells. For example, to update only German for several keys:

A … I (de_DE) …
┌─────────────────────┬─┬─────────────────────┬─┐
│ welcome_message │…│ Willkommen! │…│
│ logout_button │…│ Abmelden │…│
│ session_expired │…│ Sitzung abgelaufen │…│
└─────────────────────┴─┴─────────────────────┴─┘
Tip: Even when you only intend to update one language, your file must still contain all 56 language columns in the correct order (with the other columns empty). The importer reads columns by position, not by header name.

4How to add a brand-new key

Adding a new key is the same as updating an existing one. Just type the new key in column A and fill in the translations you have. Any language column you leave empty will fall back to the en_US value (or to the key itself if en_US is also empty), so it's fine to add a key with only one or two languages filled in initially and complete the rest in a later upload.

Tip: At minimum, fill the en_US value for every new key. This ensures the fallback chain produces a readable string in any language until the proper translation is added.

5How to add a new language

Adding a new language is not done through this page. Each language column is hard-mapped in the importer's code, so adding a new language requires a development team change. The process is:

  1. Send a request to the development team with the new language code (e.g. sv_SE) and display name (e.g. “Swedish (Sweden)”).
  2. The team appends the new language to the importer's language map, picking the next free column letter (e.g. BF) and deploys the change.
  3. The team sends you back the updated master XLS template with the new column added at the agreed position.
  4. You can then upload translations for the new language using the new template, exactly the same way as for any other language.
Important: Always use the updated template the development team sends you. Adding a column yourself in Excel without the matching code deployment will cause every column after it to be misaligned by one position, writing your values into the wrong languages.

6Before you upload — quick checklist

  • The file is saved as .xls, not .xlsx.
  • The column order in your file exactly matches the reference table above.
  • You have not inserted, deleted, or rearranged any columns.
  • You have not added formulas in translation cells — paste only values.
  • You have a backup or version history of the file before you change it.
  • You only want to change what is in this file; everything else stays as it is today.
After upload: the page will show a success message with the count of keys added and updated. To verify the change on a customer page, do a hard reload (Ctrl + Shift + R on Windows, Cmd + Shift + R on Mac) or open the page in a private browsing window so your browser cache does not show the old value.
Frequently asked questions

What happens if I leave a key out of my file?
Nothing — it stays as it is in the system. Only the keys you include are touched.

What if I upload a small file by mistake — do I lose all the other translations?
No. The importer merges into existing translations. Anything not in your upload is left alone.

How long does an upload take?
A small file (under 100 keys) should complete within a few seconds. The original full master file may take longer because of its size; that file is only needed for the one-time baseline upload.

Can I undo an upload?
Not from this page. If you've made a mistake, prepare a corrected file and upload it with the corrected values. For larger mistakes, contact the development team — there is a backup snapshot from the day the new importer went live.

Why .xls and not .xlsx?
The importer uses the older PHPExcel library, which reads .xls reliably. The full Translation Management Module (in development) will switch to PhpSpreadsheet and accept .xlsx.

How do I remove a translation I no longer want?
Removing existing translations is not supported through this upload in this phase. Translations can only be updated to a new value, not cleared. If you need an existing translation removed, contact the development team.
