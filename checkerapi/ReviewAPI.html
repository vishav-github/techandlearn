1. Overview

The Checker API is designed to allow external systems to access and process various data points within the Checker system. It facilitates seamless integration with third-party software for data retrieval and management.

2. Request

All interactions with the Checker API are performed using the HTTP POST method. There is a single, centralized endpoint for all API requests:

https://your-system-link/api_index.php

Each request sent to this endpoint must include two essential URL parameters:

  • app_id: Your unique application identifier, provided by Checker.
  • enc_request: This parameter carries your encrypted and encoded request payload.

Important Note on Security Keys

Your secret encryption key (provided by Checker) is crucial for encrypting your requests, but it is NEVER sent as a URL parameter or directly exposed in your API calls. It is used internally within your application's code to prepare the enc_request payload.

The enc_request Parameter Construction Steps

The enc_request parameter is not raw JSON; it’s a specially prepared string. Follow these steps to construct it:

  1. Prepare the JSON Payload: Begin by defining your request data as a standard JSON object. This object will always contain controller and action fields, followed by any other properties required for your specific request.
  2. Core JSON Structure: 
    
{
  "controller": "Name of the API module (e.g., 'Review')",
  "action": "Specific operation within the module (e.g., 'selectrecord')",
  // ... additional properties and data relevant to the chosen controller and action.
}
  3. Encrypt the JSON Payload (AES-256-CBC): The JSON payload must be encrypted using the AES-256-CBC symmetric encryption algorithm. Use the unique, secret encryption key provided by Checker and generate a new, random Initialization Vector (IV) for each encryption operation to ensure security.
  4. Combine IV and Encrypted Data, then Base64 Encode: Prepend the raw binary IV to the raw binary encrypted data, then Base64 encode the combined string.
  5. URL Encode: URL-encode the Base64-encoded string (using rawurlencode in PHP) before attaching it to the API URL as the enc_request parameter.

PHP Code Example (for constructing and sending a request)

This example demonstrates all steps required to prepare, encrypt, encode, and send an API request, adhering to the specified encryption and parameter requirements.


 'Review', // Specifies the API controller (e.g., 'Review' module)
    'action' => 'selectrecord', // Specifies the action to perform (e.g., 'selectrecord' within 'Review')
    'where' => array( // Filters or conditions for the request
        'SetLink' => '1977', // Example filter: Questionnaire ID
        'FinishTime' => '2024-03-03' // Example filter: Review Finish date
    )
);

// Convert the PHP array into a JSON string
$params_json = json_encode($params, JSON_PRETTY_PRINT);
echo "-JSON Payload to Encrypt-\n" . $params_json . "\n\n";

// Step 2: Encrypt the JSON Payload (AES-256-CBC)
$iv_size = openssl_cipher_iv_length('aes-256-cbc');
$iv = openssl_random_pseudo_bytes($iv_size);
$encryption_key = 'b2fg839certr469fbc3118e286d2ca4b'; // REPLACE WITH YOUR ACTUAL ENCRYPTION KEY FROM CHECKER!
$params_encrypted = openssl_encrypt(
    $params_json,
    'aes-256-cbc',
    $encryption_key,
    OPENSSL_RAW_DATA,
    $iv
);
$params_encoded = base64_encode($iv . $params_encrypted);
echo "-Base64 Encoded (IV + Encrypted Data)-\n" . $params_encoded . "\n\n";

// Step 3: Build the Complete API URL
$app_id = '30'; // REPLACE WITH YOUR ACTUAL app_id FROM CHECKER!
$url = "https://your-system-link/api_index.php?app_id=" . $app_id . "&enc_request=" . rawurlencode($params_encoded);
echo "-Constructed API URL-\n" . $url . "\n\n";

// Step 4: Send the API Request via cURL
$ch = curl_init();
curl_setopt($ch, CURLOPT_URL, $url);
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
curl_setopt($ch, CURLOPT_SSL_VERIFYPEER, true);
$response = curl_exec($ch);
$http_code = curl_getinfo($ch, CURLINFO_HTTP_CODE);
$error = curl_error($ch);
curl_close($ch);

// Step 5: Handle the API Response
if ($http_code == 200) {
    echo "✅ API Request Successful!\n";
    echo "--- API Response Data ---\n" . $response . "\n";
} else {
    echo "❌ API Request Failed!\n";
    echo "HTTP Status Code: $http_code\n";
    echo "cURL Error (if any): $error\n";
    echo "Raw Response (if received from server):\n" . $response . "\n";
}
?>

Security Warning: Never hardcode the encryption key in your script in a production environment. Store it securely (e.g., using environment variables or a key management system).

3. Response

API responses are provided in JSON format. The structure varies depending on whether the request was successful or an error occurred.

Unsuccessful Response Format

If the request encounters an error (e.g., invalid parameters, authentication issues), the response follows this format:


{
  "success": false,
  "errormsg": "A clear, descriptive error message explaining the reason for the failure",
  "security_note": "data secured"
}

Successful Response Format

If the request is processed successfully, the response contains the requested data in the data field:


{
  "success": true,
  "data": {
    // Specific data returned by the API action, varying by controller and action
  },
  "security_note": "data secured"
}

4. Specific Requests

This section details the specific API requests available, organized by controller and action. Each controller corresponds to a controller field in the JSON payload, and subsections represent the action to be called.

4.1 Review

The Review controller is used to access and filter data related to reviews within the system.

4.1.1 selectrecord

Description: This action retrieves review records based on specified filters.

Parameters:

  • where (Object): Defines filters for review fields. Combine multiple fields to narrow results.
    • CritID : (Integer) Unique ID of the review.
    • SetTypeLink : (Integer) Type of questionnaire used for the review.
    • CritMode (Integer): Mode of the review (0 for online, 1 for offline).
    • CheckerLink (Integer): ID of the shopper who performed the review.
    • ClientLink (Integer): ID of the client associated with the review.
    • BranchLink (Integer): ID of the branch where the review took place.
    • SetLink (Integer): ID of the questionnaire.
    • SetName (String): Name of the questionnaire.
    • ISurveyLink (Integer): ID of the Internet survey.
    • WorkerLink (Integer): ID of the worker.
    • ActualStartTime (Date/Time String): Date and time when the shopper began the review.
    • StartTime (Date/Time String): Declared start time of the review.
    • FinishTime (Date/Time String): Declared finish time of the review (as a date).
    • ActualFinishTime (Date/Time String): Actual time when the shopper finished the review.
    • Result (String): Overall result of the review.
    • CritStatusLink (Integer): Status of the review (e.g., 1 for pending, 6 for approved).
    • QaGradeAdjusted (Integer): Set to 1 if QA adjusted the review result, 0 otherwise.
    • QaGrade (String): Result as adjusted by QA.
    • QaUserLink (Integer): ID of the QA user who performed the adjustment.
    • WasSentBack (Integer): Set to 1 if the review was sent back to the shopper, 0 otherwise.
    • PanelistLink (Integer): ID of the panelist.
    • DataIDs (Array of Integers): Limits returned questions to specified questionnaire object IDs.
    • RemoveEmptyChapters (Boolean): If true, removes empty sections or subsections from the response.

Return Values: An object containing review data, including the review’s result, branch ID, name, and structured data (e.g., questions, sections). The content depends on the review’s structure.

Example JSON Request:


{
  "controller": "Review",
  "action": "selectrecord",
  "where": {
    "SetLink": 444,
    "ClientLink": 255
  }
}

4.1.2 getOnceApproved

Description: This action retrieves approved reviews based on specified filter criteria, often within a specific time frame or related to projects/surveys.

Parameters:

  • where (Object): Defines filters for review fields.
    • CritID (Integer): Unique ID of the review.
    • SetTypeLink (Integer): Type of questionnaire.
    • CritMode (Integer): Mode of the review.
    • CheckerLink (Integer): ID of the shopper.
    • ClientLink (Integer): ID of the client.
    • BranchLink (Integer): ID of the branch.
    • SetLink (Integer): ID of the questionnaire.
    • SetName (String): Name of the questionnaire.
    • ISurveyLink (Integer): ID of the Internet survey.
    • WorkerLink (Integer): ID of the worker.
    • ActualStartTime (Date/Time String): Date when the shopper began the review.
    • StartTime (Date/Time String): Declared start time.
    • FinishTime (Date/Time String): Declared finish time (as a date).
    • ActualFinishTime (Date/Time String): Actual time when the shopper finished the review.
    • Result (String): Result of the review.
    • CritStatusLink (Integer): Status of the review (e.g., 6 for approved).
    • QaGradeAdjusted (Integer): Set to 1 if QA adjusted review result, 0 otherwise.
    • QaGrade (String): Result adjusted by QA.
    • QaUserLink (Integer): ID of the QA user.
    • WasSentBack (Integer): Set to 1 if sent back to shopper, 0 otherwise.
    • PanelistLink (Integer): ID of the panelist.
    • FinishTimeStart (Date String): Start of the period for reviews (YYYY-MM-DD).
    • FinishTimeEnd (Date String): End of the period for reviews (YYYY-MM-DD).
    • ProjectIDs (Array of Integers): Array of project IDs to filter reviews.
    • SurveyIDs (Array of Integers): Array of survey IDs to filter reviews.
    • LastUpdateStart (Date/Time String): Start of the period for last updated reviews.
    • LastUpdateEnd (Date/Time String): End of the period for last updated reviews.

Return Values: An object containing review data, including the review’s result, branch ID, name, and structured data (e.g., questions, sections). The content depends on the review’s structure.

Example JSON Request:


{
  "controller": "Review",
  "action": "getOnceApproved",
  "where": {
    "LastUpdateStart": "2025-02-01 00:00:00",
    "LastUpdateEnd": "2025-06-14 23:59:59",
    "SetLink": 6456
  }
}
